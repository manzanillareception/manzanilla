# Action-agent model comparison (measured, 2026-11-05 ~13:18-13:23 IST)

Method: Sonic-TTS utterances streamed over the agent websocket (production protocol) to two
TEMP test agents (gemini-3.5-flash-lite agent_TEST_gemini35, claude-sonnet-5
agent_TEST_sonnet5), identical config otherwise, client tool call_guest answered
locally. No telephony. Vendor-average latency used only as a shortlist.

## Final matrix (after adding digit-combining + reply-language prompt rules)

| scenario | claude-sonnet-5 | gemini-3.5-flash-lite |
| --- | --- | --- |
| clear EN instruction (number+question) | PASS (1754ms to tool call) | PASS (1189ms) |
| missing number | PASS - asks for number | PASS - asks for number |
| missing question | PASS - asks what to ask | PASS - asks what to ask |
| tool error (calling_not_configured) | PASS - states failure plainly | PASS - states failure plainly |
| clear ES instruction | PASS, replies Spanish (1947ms) | PASS, replies Spanish (1489ms; 686ms on first run before language rule) |

Before the prompt rules: sonnet failed EN digit strings (asked for confirmation instead of
combining spaced digits - safe but no completion); gemini replied in English to a Spanish
instruction. Both fixed by prompt rules, not model change.

Latency note: end-of-input-audio to first response audio ranged 531-1600ms (gemini) and
969-1953ms (sonnet) across single runs - overlapping ranges, small n; vendor averages
(596 vs 731ms) match the direction but are not the deciding evidence. Tool semantics,
clarification behavior, error honesty and language discipline all pass on both with the
final prompt.
